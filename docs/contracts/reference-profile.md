# Reference profile: explicit bootstrap and inspected standing

This candidate profile encodes one consumed object class, standing, with algorithm sha256, semantic digest, separate transport blob digest and an explicit source URL. Every field occurs once in fixed order; exact encode/decode round trip is required. Unknown classes and algorithms, duplicates, missing or extra fields, credentials, fragments and noncanonical encoding refuse by name. The source is a locator, never authority or independence. Schemes are a host policy; this sample allows https only.

The transport wrapper is exactly the UTF-8 bytes of JSON.stringify({profile:"semantic-standing@1",standing:<canonical text>}), in that property order, with no whitespace or final newline. JSON is decoded by the platform JSON decoder, then exact reconstruction is compared. Duplicate members, including duplicate members whose final parsed value would be valid, refuse even when their blob hash matches. Invalid UTF-8 refuses. This wrapper is a candidate transport profile, not a published universal JSON canonicalization contract.

Blob integrity is verified before wrapper interpretation. Existing Topos readSemanticStanding and semanticStandingBytes validate and project in effective order, then the semantic digest is checked. Bad blob bytes are an integrity refusal, never a fork. Different admitted claims may conflict; this inspector neither admits nor authenticates claims and performs no encounter algebra.

Native samples hand the source response bytes through the reader's declared inputs. The synchronous inspector receives only those handed bytes. The host's node:crypto hash primitive verifies their digests; Topos supplies semantic parsing/projection. No network request occurs in the reader. This pays native inspection of explicitly supplied source bytes, not native content-request transport resolution. The earlier Node/browser bootstrap exercises the HTTP host separately. A native fetching port remains an explicit unpaid integration demand.

The native direct reader is declared with bounded lifetime and response bytes. Its resource limits are fixture policy. Selection, help, check, preview and sign do not invoke a transport adapter. No key, private store or remote source is required by a clean sample consumer. The package includes the selected reader as public sample support; no private runner is a public use command.

Two unrelated places use different canonical standings (catalog counts and route notes). Both print attributed conformance readings through Bound's receipts view; these are inspected readings, not states or authenticated authority. Each has a yes place and a no place whose duplicate-member wrapper has a correctly recomputed blob hash. The no place refuses `REFUSE·reference noncanonical document wrapper`. Reader dependencies are bundled from the existing implementation with an explicit module inventory; no algebra is copied or reimplemented.


`semantic-standing@1` remains an inspection projection. Its bytes and reference do not authenticate their declarations. An authenticated opening additionally consumes an `authenticated-standing@1` carrier: the UTF-8 bytes of `JSON.stringify(["authenticated-standing@1", originals, proof]) + "\n"`, where originals are canonical signed wire lines in supplied order and proof is a canonical signed wire declaration. The carrier is a transport envelope, excluded from standing identity.

The host selects the authority snapshot, authority epoch, proof scope, trusted public signers and coverage, signature eras, origin and witness policy, and selected form standing and implementation. They are external trust inputs; neither source URL, carrier, digest nor embedded key creates authority. The proof has `role=writes form=alphabet measure=digest`, its value commits to `JSON.stringify(["authenticated-standing@1", originals]) + "\n"`, and `at=witness:<snapshot>` binds the selected snapshot. Its signed epoch equals the selected authority epoch. Existing native authority and signature validation applies. Original lines are authenticated historical evidence; the current snapshot proof is evaluated at the host's current authority epoch. This inspection does not authorize reusing an answer as current.

After authentication, existing object-history validation applies with both signature admission and the host's declared admission policy. Existing semantic-live@2 cell cones determine live typed membership only. The original globally effective order (ascending epoch, supplied stable order within an epoch) determines standing order. All live configuration remains included. A configuration withdrawal requires the admitted standing fold and otherwise refuses by name; no configuration-history semantics are inferred. Typed authorized withdrawals use the existing validator and live projection. The semantic digest excludes retired typed claims and withdrawal envelopes; it retains configuration and effective order.

The host fixes finite byte and record budgets and bounds transport before handing over bytes. Shared transport buffers refuse; owned copied bytes are hashed and decoded. Verification completes before prepared records are returned. No writer or commit port is exposed by this opening. Authority-context identity commits to host snapshot, epoch, proof scope, origin/admission policy identity, form implementation identity, signers with coverage and signature algorithms. Form standing and executable implementation remain distinct identities.
